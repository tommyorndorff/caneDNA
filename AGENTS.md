# AGENTS.md

Canonical AI-assistant instructions for **caneDNA**. Tool-specific files
(`.claude/CLAUDE.md`) delegate here.

## What this project is

caneDNA is an open-source taper explorer for split-bamboo fly rods — a modern,
open reimagining of Larry Tusoni's RodDNA. It ships a merged, attributed library
of rod tapers and a GUI (native desktop **and** browser/WASM) to browse, filter,
and overlay-compare them. The long-term goal is to explore and design rod
patterns (4-piece travel rods, single- and double-handed spey rods).

## Architecture & data flow

- **Two crates.** `roddna-core` owns the data model (`Taper`, `Provenance`,
  `Library`) and JSON loading; it has no GUI dependencies and carries the parse
  test. `roddna-gui` is the eframe/egui UI and depends on core.
- **The library is a build artifact.** Python importers each read one source into
  `data/sources/<name>.json`; `build_library.py` merges them into
  `data/tapers.json` (currently **873 models** from 3 sources). The GUI embeds
  that file at compile time via `include_str!`, so the app — native or web — needs
  no runtime data files or backend.
- **Dedup is dimension-aware.** `build_library.py` collapses two records only when
  name **and** taper dimensions match within `--tol` (default 0.0015"); same-named
  rods with genuinely different tapers are kept and disambiguated with a source
  tag. Original names are preserved in `provenance.orig_name`.
- **Provenance is per-taper.** Every record carries a `provenance` block (source,
  author, url, collection, license, imported date). Preserve attribution when
  adding or transforming data — see the Data Sources table in `README.md`.

## Conventions

- **Regenerating data:** never hand-edit `data/tapers.json` or `data/sources/*`.
  Change an importer or `build_library.py` and re-run the pipeline (see HOWTOAI.md).
- **One GUI, two targets:** keep platform-specific code behind
  `#[cfg(target_arch = "wasm32")]` / `#[cfg(not(...))]`. The `App` and all logic
  stay shared.
- **Commits:** use [Conventional Commits](https://www.conventionalcommits.org)
  (`feat:`, `fix:`, `chore:`, …) — release-please derives versions and CHANGELOG
  from them.
- Python scripts target stdlib + `openpyxl` (for xlsx). Keep them runnable as
  standalone `python3 scripts/<name>.py`.

## Build / test / run

```sh
cargo test -p roddna-core                 # parse + validate the library
cargo run  -p roddna-gui                  # native desktop app
cd crates/roddna-gui && trunk serve       # web app at localhost:8080
```

See `HOWTOAI.md` for the full data-pipeline and web-deploy commands.

## Gotchas

- `data/tapers.json` is embedded at compile time — after regenerating it, rebuild
  `roddna-gui` for changes to appear.
- The web build needs `rustup target add wasm32-unknown-unknown` and `trunk`.
- `import_hexrod.py` / `import_taper_sheets.py` require `openpyxl`.
